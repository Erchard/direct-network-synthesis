# DNS 0.5 Hybrid Prototype Diagnostic

Status: locked before development evaluation, 2026-09-06.

Question: can a fixed mixture of class-local synthetic coverage centers and a
small predetermined boundary-center allocation improve the train-sample-free
prototype candidate? This is a validation-only diagnostic on reused digits
development splits. It is not test evidence and not a novelty claim.

1. Use the same digits split seeds 101, 202, 303, 404 and 505 at 60/20/20. Only
   train and validation arrays enter evaluation. Excluded split members are not
   transformed, predicted or scored. Test fields are null.
2. Use train-only standardization and the same shared RBF oracle selection grid:
   gamma multipliers [0.5, 1.0, 2.0] and alpha [0.001, 0.01, 0.1]. Reuse the
   selected gamma for all RBF-derived features in each split.
3. Evaluate only already defined references plus one new family at the locked
   192-center budget: linear, fixed ReLU 256, PCA ReLU 192, compiled 192, RFF
   192, class-PCA prototypes 192, dipole prototypes 192, hybrid prototypes 192,
   uniform Nystrom 192, spectral 192 and full RBF.
4. Define `prototype_class_hybrid_192` as 152 class-PCA synthetic coverage
   centers plus 40 boundary centers. The boundary allocation is two rival-axis
   pairs per class for the ten digits classes. This allocation is fixed before
   evaluation and is not a validation grid.
5. Class-PCA coverage centers are generated by the existing train-only
   class-local centroid plus PCA/quantile rule. Boundary centers use the existing
   nearest-rival rule from DNS05-DIP: for each class, choose the other class with
   highest mean cross-class RBF affinity under the selected train-only gamma,
   then place paired centers at class-local PCA/quantile offsets shifted by
   +/- 0.25 of the class-centroid-to-rival-centroid vector.
6. Prototype features use the same explicit map as Nystrom:
   `K(X, C) K(C, C)^(-1/2)`, with `C` equal to synthetic centers and the same
   eigenvalue cutoff rule. Record retained real train samples, prototype count
   and exact train-row prototype matches.
7. For every representation evaluate alpha [0.001, 0.01, 0.1, 1.0] and
   intercept [false, true] using the same closed-form readout objective as the
   previous diagnostics. Select by validation accuracy per model/split, then
   smaller alpha, then no intercept.
8. Report validation accuracy, RMSE, R2, train kernel reconstruction error,
   realized rank, feature budget, retained real train samples, prototype count,
   prototype/train exact-match count, solve time and inference time. Report all
   variants, including negative outcomes.
9. Planned selected paired differences: hybrid prototypes 192 minus dipole
   prototypes 192, hybrid prototypes 192 minus class-PCA prototypes 192, hybrid
   prototypes 192 minus uniform Nystrom 192, hybrid prototypes 192 minus fixed
   ReLU 256, hybrid prototypes 192 minus compiled 192, hybrid prototypes 192
   minus spectral 192, dipole prototypes 192 minus uniform Nystrom 192 and
   uniform Nystrom 192 minus spectral 192.
10. Do not adapt the hybrid allocation, shift fraction, quantiles, budgets,
    readout grid or seeds after seeing validation outcomes. Any later variant
    inspired by this run requires a separate locked protocol.

Decision: keep the hybrid candidate only if it gives a meaningful and stable
validation improvement over dipole prototypes while retaining zero train samples
and no exact train-row center matches. If it does not improve, close the
hybrid-center branch as a negative development result and choose fresh
confirmation data for already selected candidates instead of tuning this formula.
